# Project: GDC BAM -> FASTQ -> Salmon (TCGA-LIHC)

Nextflow (DSL2) pipeline that, for every sample in a samplesheet, downloads the GDC STAR
"2-Pass Genome" RNA-seq BAM, reverts it to paired FASTQ, quantifies it with Salmon against
GENCODE v49, and then deletes the large intermediates. Goal: re-quantify all TCGA-LIHC RNA-seq
samples (about 424 BAMs, tumor and normal) with GENCODE v49 instead of the v36 used by GDC.

Origin: ported from a WDL (`rna-quantification.wdl`, a single `salmon quant` task) and then extended
with download, BAM->FASTQ, cleanup, GDC metadata lookup and a Salmon-only mode.

## Files

| File | Purpose |
|---|---|
| `main.nf` | Pipeline. Processes: `DOWNLOAD_BAM`, `BAM_TO_FASTQ`, `SRA_TO_FASTQ`, `UNTAR_INDEX`, `SALMON_QUANT`, `CLEANUP`, `QUANT_FROM_GDC`, `QUANT_FROM_SRA`. |
| `nextflow.config` | All params + defaults, per-label resources/containers, profiles (`standard`, `docker`, `singularity`, `slurm`). Params are defined here, NOT in main.nf (config is parsed before the script). |
| `fetch_gdc_metadata.py` | Stdlib-only script that queries the public GDC API and writes the samplesheet. |
| `fetch_sra_metadata.py` | Stdlib-only script: queries SRA for a BioProject, joins DepMap `Model.csv`, filters by `OncotreeLineage`, writes the SRA samplesheet. |
| `download_sra_fastq.sh` | Pre-download SRA runs to FASTQ and emit a `fastq_samplesheet.csv`. For **Gadi only** (see below); runs under PBS (`qsub`) or plain `bash`. |
| `docker/Dockerfile.sra` | Image for `QUANT_FROM_SRA` (sra-tools + salmon + pigz), the SRA counterpart of `docker/Dockerfile`. |
| `lihc_star_genome_query.json` | Request body for the GDC `/files` endpoint (same query the script uses; from `--print-query`). |
| `samplesheet.csv` | EXAMPLE only (placeholder UUIDs). Real samplesheet is generated by the script. |

## How it works

1. `python3 fetch_gdc_metadata.py --project TCGA-LIHC -o samplesheet.csv` builds the samplesheet.
   Filter: project TCGA-LIHC + data_type "Aligned Reads" + data_format BAM + RNA-Seq +
   `analysis.workflow_type` = "STAR 2-Pass Genome" (expect 424 files before exclusions).
   - Output columns: `sample,gdc_file_id,case,tissue_type,sample_type,tumor_descriptor,project_id,file_name`
   - `sample` = TCGA sample barcode (e.g. `TCGA-BC-A110-01A` tumor, `-11A` normal); made unique per file.
   - `tissue_type` comes from the API (falls back to the barcode code: 01-09 tumor, 10-19 normal).
   - Recurrence samples are excluded by default (3 in LIHC; `--include-recurrence` keeps them).
   - Cases with both Tumor and Normal are listed first.
   - Writes good rows and exits 1 if some files had problems.
2. `main.nf` reads only `sample` and `gdc_file_id` (extra columns are ignored).
3. Per sample: `DOWNLOAD_BAM` (gdc-client + token) -> `BAM_TO_FASTQ` (`samtools collate -u -O | samtools fastq`,
   unmapped reads kept; fails if R1 is empty; writes singleton count to `results/fastq_stats/`)
   -> `SALMON_QUANT` (`-l A --seqBias --gcBias --dumpEq --geneMap`, publishes `results/<sample>/`)
   -> `CLEANUP` (deletes the BAM + FASTQ real files in `work/` via `readlink -f`; only runs after
   SALMON_QUANT succeeded and quant.sf is non-empty).
4. Alternative entry point: `--fastq_samplesheet` (CSV `sample,fastq_1,fastq_2`, absolute paths) runs
   only Salmon (no download, conversion or cleanup).
5. Alternative entry point: `--sra_samplesheet` (CSV `sample,srr_run`) for the CCLE/DepMap cell lines,
   whose RNA-seq is in SRA BioProject PRJNA523380. Public data: no token.
   `SRA_TO_FASTQ` (prefetch + `fasterq-dump --split-3`) -> `SALMON_QUANT`; with `--fused true`,
   `QUANT_FROM_SRA` does all three on one VM's local disk. CLEANUP does not apply (SRA_TO_FASTQ
   deletes the `.sra` and the uncompressed FASTQ inside its own task).
   - Samplesheet: `python3 fetch_sra_metadata.py --bioproject PRJNA523380 --model-csv Model.csv
     --lineage Liver --paired-only -o sra_samplesheet.csv`
   - The script filters server-side (`"RNA-Seq"[Strategy]`): PRJNA523380 is **mixed-assay** --
     4,550 experiment packages of which only **1,019** are RNA-Seq (the rest are mostly WGS), and
     all 1,019 are PAIRED. Without that filter you page through 5x the data and would hand WGS runs
     to Salmon.
   - Cell line comes from the SRA `cell line` SAMPLE_ATTRIBUTE / TITLE (e.g. `VM-CUB1`, `ZR-75-1`),
     normalised to letters+digits and matched against `CCLEName` / `StrippedCellLineName` / `ModelID`.
     Lineage is taken from DepMap's curated `OncotreeLineage`, NOT the free-text `_LIVER` suffix of
     the CCLE name -- same convention as `build_ccle_reference.R`.
   - Unmatched runs are excluded and the script exits 1 naming them: a liver line missing from
     `Model.csv` would otherwise silently shrink the cohort.
   - Several runs per cell line are normally lanes of one library: merge with `--merge_same_sample true`,
     or pass `--one-run-per-line` to the script (required for `--fused`, which needs one run per sample).

### Where to run the SRA/CCLE path

CCLE RNA-seq in PRJNA523380 is **open** data (no token, no dbGaP), so it can run anywhere.

- **GCP VM / laptop**: use `--sra_samplesheet` directly; the pipeline downloads as part of the run.
- **Google Batch**: `--sra_samplesheet --fused true` (`QUANT_FROM_SRA`), same reasoning as the GDC
  fused mode -- no `.sra` or FASTQ crosses the bucket.
- **Gadi**: the pipeline canNOT download during the run. Only `copyq` has outbound network and it is
  capped at 1 CPU; `normal` has the CPUs but no network. Three stages (modules: `sra-tools/3.2.1` from
  `/g/data/io72` so jobs need `gdata/io72` in `-l storage`; `nextflow/25.04.6`; `salmon/1.10.1`):
  1. `qsub prefetch_sra.sh` on **copyq** -- `.sra` only (~8.5 GB/run, ~11 min). Idempotent via `.done` markers.
  2. `qsub dump_sra_fastq.pbs` on **normal** (16 CPUs, temp in `$PBS_JOBFS`) -- fasterq-dump + pigz, writes
     `<OUTDIR>/fastq_samplesheet.csv`. CCLE runs are aligned cSRA, so this needs the reference sequences that
     prefetch stored under `<OUTDIR>/ncbi` (same `NCBI_SETTINGS` file in both stages).
  3. `qsub run_salmon.pbs` on **normal** -- `--fastq_samplesheet` mode; pre-downloaded FASTQs are inputs so are never deleted.
  `download_sra_fastq.sh` still does 1+2 in one 1-CPU copyq job (measured: SRR8616130, 16.4 Gbases: 64 min =
  11 prefetch + 16 fasterq-dump + 37 single-thread gzip). Both assumptions below were verified by that run:
  `fasterq-dump` on a `.sra` path writes `<SRR>_1/_2.fastq`, and the inline `user-settings.mkfg` works.

Typical commands:

```bash
# test: first 2 rows (first tumor/normal pair), no bootstraps
nextflow run main.nf --samplesheet samplesheet.csv --limit_rows 2 \
  --gdc_token /data/controlled_data/gdc-user-token.<date>.txt \
  --salmon_index /data/annotation/salmon_index \
  --gene_map /data/annotation/gencode.v49.genemap.tsv.gz \
  --num_bootstraps 0 --outdir results_test

# resume a specific run (see gotchas)
nextflow run main.nf -resume <FULL-SESSION-ID> <same args>
```

Parameters worth knowing: `--limit_rows N`, `--skip_rows M` (batching), `--num_bootstraps` (config default
100, we want 0), `--max_downloads`, `--cleanup true|false`, `--merge_same_sample`, `--outdir`.

## Environment and data (the author's setup)

- GCP VM `e2-standard-16` (16 vCPU, 64 GB), project dir `~/milestone3`, conda env `nextflow`:
  Nextflow 24.10.6, openjdk 17, Python 3.11, gdc-client, samtools 1.20, salmon 1.10.x on PATH.
  No container runtime in use: run with the default profile, tools come from conda
  (container settings are ignored unless `-profile docker|singularity`).
- Python 3.14 breaks gdc-client (`Can't pickle local object ... download_worker`); keep Python <= 3.13.
- Salmon index `/data/annotation/salmon_index` (17 GB, decoy-aware, GENCODE v49, 517,232 targets incl. 194 decoys).
  Needs roughly 20+ GB RAM to run Salmon.
- Gene map `/data/annotation/gencode.v49.genemap.tsv.gz`: 2-column TSV (transcript ID -> gene ID, versioned IDs, no header).
  Names must match the index target names (they do: `quant.genes.sf` had 82,051 genes).
- GDC controlled-access token under `/data/controlled_data/` (expires ~30 days). NEVER commit tokens.

## Gotchas / decisions (do not undo without a reason)

- One BAM = one sample. Rows with the same `sample` are merged into one Salmon run (WDL-style lanes) and the
  pipeline now errors unless `--merge_same_sample true`. `groupKey(sample, n)` lets samples stream through
  `groupTuple` instead of waiting for all samples.
- Only the GENOMIC STAR BAM contains the unaligned and chimeric reads needed to rebuild complete FASTQs;
  the transcriptome and chimeric BAM sets are NOT sufficient.
- `-resume` needs the FULL session ID (`nextflow log`); a run name was ignored and the last session was used.
  Nextflow options take one dash (`-resume`), pipeline params two and use underscores (`--num_bootstraps`).
  After CLEANUP the BAMs/FASTQs are gone, so resuming those samples re-downloads them.
- The gene map keeps its original name when gunzipped (`${gene_map.baseName}`): Salmon decides GTF vs TSV by
  the file extension, so a TSV must not be renamed to `.gtf`.
- Bootstraps dominate Salmon runtime (about 3 h vs about 14 min per sample here); `--dumpEq` adds output size.
- CLEANUP relies on symlink staging + `readlink -f`, so it only works on a local/shared filesystem (not Google Batch).
- Sample names are used as directory names under `--outdir`.

## Google Batch / fused mode (written, NOT yet run on Batch)

- `--fused true` runs one task per sample (`QUANT_FROM_GDC`): download -> BAM->FASTQ -> Salmon on the task's local
  disk; BAM is deleted once the FASTQs exist, FASTQs once Salmon succeeded; only `results/<sample>/` and
  `fastq_stats` are published. No big files cross the bucket. One BAM = one sample (errors on duplicates).
- `-profile google_batch`: executor `google-batch`, Spot VMs (`maxSpotAttempts = 5`, exit 50001 retried),
  project `amaroq-495623`, location `us-east1`, workDir `gs://garvan-dbgap-controlled/nextflow-work`,
  `executor.queueSize = 20`. Keep bucket, Batch jobs and Salmon index in ONE region (us-east1): cross-region
  reads of the 17 GB index x 421 samples would cost more than the compute.
- Fused tasks need ONE image with gdc-client + samtools + salmon: `docker/Dockerfile` (build with Cloud Build,
  tag in `params.fused_container`; untested). `label 'fused'` = e2-standard-16, 150 GB disk.
- Tested only with fake gdc-client/samtools/salmon shims on a Mac (script logic, wiring, cleanup, outputs).
  NOT tested: the image, real Batch run, how the Salmon index is read from `gs://` (copy to local disk if slow),
  where `disk` lands, the GDC token being staged into the bucket workDir (delete `nextflow-work/` afterwards).
- `num_bootstraps` default is now 0. CLEANUP now resolves symlinks before deleting and also removes `.bai`/`.csi`.
- Estimate: ~210 VM-hours of e2-standard-16 for 421 samples (~$55-115 compute); first do a 2-sample Batch run
